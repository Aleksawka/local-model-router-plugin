# Local Model Router для GitHub Copilot App

Пересылаемый экспериментальный пакет для сценария:

- основная модель: локальная Qwen Senior через oMLX;
- младшие роли: локальная Qwen Junior через oMLX;
- интерфейс: GitHub Copilot App;
- компьютер: MacBook Pro с 48 ГБ unified memory;
- цель: проверить, может ли Copilot plugin перехватывать уже созданное делегирование и заменять профиль саб-агента на подходящий профиль с закреплённой моделью.

Пакет не меняет встроенный режим `Auto` и не является собственным model gateway. Он реализует более узкую и проверяемую гипотезу:

1. Senior решает вызвать инструмент `task`.
2. `preToolUse` hook видит этот вызов.
3. В режиме `audit` hook безопасно фиксирует структуру аргументов.
4. После подтверждения схемы режим `rewrite` может заменить выбранный профиль агента.
5. Поле `model:` выбранного профиля направляет запрос в Qwen Junior.

## Что находится в архиве

- локальный Copilot marketplace;
- plugin `local-model-router`;
- Senior-orchestrator и три Junior-профиля;
- audit-first hook и отключённый по умолчанию режим rewrite;
- детерминированная начальная routing policy;
- скрипт подстановки точных model ID;
- автономные unit-тесты hook без Copilot и oMLX;
- небольшой fixture-репозиторий для сквозной проверки;
- подробная инструкция по установке и acceptance test plan.

## С чего начать

1. Прочитать [INSTALL-COPILOT-APP.md](INSTALL-COPILOT-APP.md).
2. Подставить точные model ID, видимые провайдеру Copilot.
3. Выполнить локальные тесты plugin.
4. Установить marketplace через Copilot CLI и полностью перезапустить App.
5. Пройти сначала audit-тесты из [TEST-PLAN.md](TEST-PLAN.md).
6. Включать `rewrite` только после подтверждения реального поля agent ID в `toolArgs`.

## Важная граница

Hook не может сам инициировать делегирование и не выбирает модель основного сеанса. Он может изменить только уже предложенный Senior вызов `task`. Поэтому основной сеанс для этого эксперимента должен быть явно зафиксирован на Qwen Senior, а не на `Auto`.
